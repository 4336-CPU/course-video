# 旁白写法细则

每一条都对应过一次返工。例子来自一门讲 AI Agent 的系列课，换成你自己的主题时照搬规则，不照搬例子。

## 结构

- **先做教学设计，再写稿。** 先写出「看完能做到什么」（2 到 4 条），按 Gagné 九步里适合视频的几步排：抓注意（一个反常结果）→ 解释原因、引出概念 → 用同一个例子讲清机制 → 放大到真实任务 → 用一张总图收住 → 预告下一集。只讲达成目标需要的内容，其余放到后面几集。
- **第一集只讲概念和全貌。** 各部分的实测例子和跑分放到专门讲那部分的那一集。
- **开门见山。** 第一句直接讲「X 是什么」或本集结论。不写「这节课回答两个问题」「这节课讲清楚……」这类预告句，不铺垫「先说一个很常见的场景」。
- **开头 2 分钟内进入本集主题。** 规划里列的案例，先确认它和本集要回答的问题是同一件事再放。前几集讲过的结论不在开头重讲。
- **标题里每个关键词都要占一节，并在前 1 分钟被说到。** 写完按句数估算每节起止时间再交稿。
- **每集自成闭环。** 开头提出的问题，结尾要答完。只跑过一次、本集收不住结论的实验，留给能收住的那一集。
- **偏题的内容一两句带过。**
- **结尾一句预告下一集**，不放和主线脱节的段落，不用「一个循环，三个工具，一个停止条件」这种排比收尾。
- **每集开头有片名卡**（第 N 课 / 课名）和一句问候，片尾标题用规划里的正式名称。

## 一条主线

- **一集一个例子讲透。** 选一个观众见过的具体对象，让它从出错走到改对，每一节都是它的下一步；讲透以后用一句话加一张图推广到全部数据。
- **不按意见往上叠段落。** 每加一段先问：它是不是主线的下一步？只是同一件事换个角度的，不加。
- **按时间顺序讲过程，先给总数。** 「这组训练一共要跑30轮，跑完第12轮时显存不够，程序停了。程序接着训练时，重新从第1轮开始记。」不用「断开以后的轮数」这种压缩说法。
- **同一个词指两样东西时，每次都带限定词**（「日志里写着第7轮」「全程第19轮」）。
- **专有说法只在第一次用白话讲清**，之后用画面或「这一组」指代。交稿前数一遍它出现了几次。
- **同一个判断全片只讲一次**，放在最该讲的那一节，别处回指。
- **不拿观众没听过的名字贴标签。** 要引用，先交代是谁、做了什么、结论是什么。只为「显得有出处」的引用删掉。
- **段与段要接得上。** 查五类问题：自相矛盾、话题突然跳、因果没说出来、语气突然转换没有提示、代词指代不清。同一件事不在两段里各讲一遍。把各节第一句连起来读，应该是一段完整的论证。

## 句子

- **言之有物。** 删掉也不影响论证的句子一律删。
- **说人话。** 「这回模型的反应就不一样了……注意，到这一步文件还没被打开」改成「模型没法自己调用工具。它能做的，是写一条请求。」
- **一句话只讲一件事**，越短越好。
- **不先念名字。** 概念不能用「名字 + 逗号/冒号/决定/就是」开头，也不用「X 要解决的问题是」。先讲它应对的具体情况，讲完再顺带说「这件事叫……」，或者名字只出现在画面上。一串概念讲完后统一点一次名，不每件事后面都「这叫 X」。
- **语序按说话的顺序：谁、做什么、结果怎样。** 这是最常犯的错，每版逐句查：
  - 不把目的放句首再用「得」「要」接动作：「要让越界的请求执行不了，检查得写进函数里」→「只有把检查写进函数里，越界的请求才会执行不了」。
  - 不把宾语或疑问小句提到句首：「错在哪一步，可以回到 trace 里查」→「我们可以回到 trace 里，查一查它错在哪一步」。
  - 条件和结果用成对的关联词（只有……才……、如果……就……、之所以……是因为……），主语写出来。
  - 判断标准：只听一遍，听到前半句就知道在说谁、在做什么。
- **不用画面方位描述概念。** 「模型在正中间，外面有五个组件」不对，概念之间是谁调用谁、谁管什么。
- **信息密度要低。** 一节只讲一件事；一个部件最多一个例子；一句话最多一个新名词；连续两句都在引入新概念时，中间插一句大白话解释。
- **不用这些句式**：自问自答（全片最多一次「先猜一下」）、「不是……而是……」、「不 X，只 Y」「没有 X，只有 Y」（直接说它会做什么）、破折号、排比收尾、加强语气的套话。交稿前全篇搜「只」「不」逐句过。
- **抛问题直接写成问句。** 未知信息放句首（「这份日志里哪一轮的验证准确率最高？」好过「一份训练日志里，最好的验证准确率出现在第几轮？」），删掉没信息量的修饰，问题里要出现本集的主题词。
- **抛编号问题前先说一句**「这节课我们来看两个问题」，不突然说「第一个问题」。
- **「可见」不要每段都用**，总结句直接陈述。主谓之间不加多余逗号。

## 例子

- **具体对比，不要抽象概括。** 好：「比如这一组，应该填19，它填了7。」差：「它没能正确换算成总轮数。」
- **每个例子后面点明结论**，不让观众自己猜。「它回答『第85轮』，可那份日志一共只有30轮。」后面接「模型根本打不开文件，它只是根据问题编了一个看起来合理的答案」。
- **需要心算的过程交给画面**（折线断开、标 12 + 7 = 19），旁白只说结果。
- **不堆砌。** 每个例子都挂在本节结论下面，同一个数字只细讲一次。
- **优先用直观的例子。** 讲「验证」时，「200 多项功能先全部标成未通过，测过一项改一项」比讲轮数换算好懂得多。
- **每个数字都要服务于所在小节的结论**，删掉它论证还成立就删。不报行数这类无关数字，不加「真跑一次」的「真」这类强调字。
- **长数字不念。** 0.7104 这类只放画面，口播说「对不上」「低了很多」；口播只留分数、次数、百分比。一句里不连报三个数。

## 严谨

- 数字只用两种来源：自己实跑的记录（存进工程目录），或者核对过的原文（官网、论文、官方榜单）。
- 模型输出每次不一样，录制以存下来的那份记录为准，不重跑。
- 只跑过一次的实验不说成定论。榜单分数带上误差范围再下结论。
- 找不到原始出处的说法删掉。别人的实验和你的不是同一个任务时，说「论文也测过这件事」，不说「相同结果」。
- 写完每个因果句，对照实验记录确认真的是这样。
- 引用论文时口播说作者和年月，不念长题目，题目放在截图上高亮。
- 「科学严谨不要钻牛角尖」：严谨是为了不说错，不是为了把每个细节都讲出来。

## 上下集承接

- 开头一两句接住上一集结尾的预告，紧接着给本集结论。不写「上节课我们讲了……这节课我们来……」。
- 沿用前几集的术语、贯穿任务和成绩，前几集讲过的数字一句带过。
- 回指前几集要说清那次具体发生了什么（「第 2 课那组填了第 7 轮的实验」），不写「这里也是同一个思路」。
- 结尾回指「开头的问题」时，开头必须真的提过问题。

## 主语和指代

- 每句说清是谁在做：「harness 会先列出 200 多项功能」，不写「他们先列出」。
- 第一次提到的东西先交代是什么，再用代词指它。
- 用具体事实替代指代：「这两个数在日志里都找不到」→「根本不存在第85轮」。

## 配音稿精修（交给 TTS 前逐句过）

1. 中英文、中文和数字之间不留空格，TTS 会在空格处停顿。
2. 逗号就是停顿，只放在真要停的地方。短状语后、主谓之间不加。
3. 同一句里主语、数字只说一次，第二次用「上限」这类回指。
4. 删掉不推进内容的半句，画面已经表达的旁白不重复说。
5. 字幕每句单独一条，句号、问号后一定另起一条。
6. 字幕改了以后，读法、停顿表、画面里按词对齐的动画锚点都要同步检查。

## 五遍润色（每一版都主动做）

1. pyramid-principle：结论先行，例子后有点明句，每层单独能看懂。
2. technical-writing：删掉只在主持流程、不提供信息的句子。
3. plain-writing：每段先给主题句再给一个例子；一句最多两个分句；不连给三个例子；不用冒号连两个分句；过程按「第一、第二」逐句走。
4. coherent-writing：逐段查段内逻辑和段间衔接。
5. humanizer：口语化大改，几乎每句都重写，只改几个词不算做过。

用户自己改过的句子例外，直接用他的版本。

## 交稿前自查清单

- [ ] 第一句是不是直接讲「X 是什么」或本集结论？有没有预告句、场景铺垫？
- [ ] 开头 2 分钟内进入主题了吗？标题里每个关键词都在前 1 分钟出现了吗？
- [ ] 每节第一句是不是结论？每个例子后面有没有点明结论？
- [ ] 每个数字是不是都服务于所在小节的结论？长数字是不是只放画面？
- [ ] 有没有一句话塞了两件以上的事、读不通的病句、主语或量词错？
- [ ] 每节是不是只讲一件事？有没有连续几句都在抛新名词？相邻两句有没有重复？
- [ ] 有没有先念名字的开头、方位描述概念、自问自答、「不是……而是……」「不……只……」、破折号、排比收尾？
- [ ] 语序是不是「谁、做什么、结果」？
- [ ] 开头的问题结尾答完了吗？结尾是不是一句预告？
- [ ] 和前几集的术语、数字、例子是否一致？
- [ ] 每个数字在「出处与核实」里都有记录文件或原文吗？
- [ ] 五遍润色都用 Skill 工具调用了吗？
- [ ] 时长是否达到要求？
