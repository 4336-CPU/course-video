# 画面规则与渲染细节

## 风格

- **引擎**：vibe-knowledge-film（MIT）的「夜曲」暗场风格。主题 `night`，bloom 0.6，grain 0.025，30fps，1080p。
- **不用视频生成模型。** 讲解靠代码逐帧画，数字和文字才能精确可控。用视频生成模型做的「机器人演示片」会被嫌太抽象。
- **配色有固定含义**，例如冰蓝是结构，金色是关键数字和关键词，玫红是错误。一部片子里一种颜色只表达一种意思：前面用绿表示「答对」，后面就不能用绿表示「来源」。画新图前先查全片已经用过的颜色含义。
- **字体**用开源字体（引擎自带 Noto Sans/Serif SC）。商用字体要先确认授权。字幕用衬线字。代码字体关掉连写，否则 JetBrains Mono 会把 `!=` 画成 `≠`：`font-feature-settings: "liga" 0, "calt" 0`。
- **风格参考视频**：模型看不了视频，只能读用户下载的文件抽帧，或者读简介和源码，要如实说。

## 前后集视觉一致

- 新一集开工前，先对上一集跑 `--sheet 24`，看清用过哪些视觉元素。同一个概念在各集用同一种画法（例：模型画成转动的光环，外层程序是外圈，上下文是发光窗口条，工具是卡片，对话是一串消息卡）。
- 配色、字体、字幕样式、镜头节奏、片尾资料卡格式都和上一集一致。
- 讲到前面讲过的东西，直接把那一集的画面元素拿回来，让观众一眼认出。每节至少用一个前几集的元素。
- 新造的组件放进 `common.js`，后面复用。

## 像视频，不像 PPT

- 句子里说到什么，屏上就发生什么，动词要真的发生（「飞进模型」「展开成图表」「划掉改成 19」）。
- 每一镜遮住字幕问三个问题：这是什么，它在干什么，观众看懂了什么。
- 静止画面最长 3 秒。没念到的东西不提前露面。
- 可视化本身就是数据：一颗粒子就是一个 token，48 颗和 2071 颗真的流进模型。
- 文本框只放真实原文（代码、日志、网页截图、报错）。过程用真实对象的动作表现：日志卡压扁成一行、数字飞进表格、循环被切断再接上。少用一排排文字卡片讲事。
- 抽象可视化太多会「眼花缭乱没有逻辑」，要配真实素材。
- 讲代码时，画面主体放代码运行时发生的事，代码缩成角落的小面板，每次只放当前讲的一到三行。可以做一张全片共用的「运行舞台」，每节只点亮正在讲的部分。
- 同一个布局不能一直不动。每段旁白开始时镜头缓缓推向正在讲的那一块（最多 1.05 倍，焦点只往画面中心挪 15%），四周用径向渐变压暗，讲完拉回全景。

## 讲解画面的设计

（借鉴 NousResearch/hermes-agent 的 manim-video 和 yudong-94/storytelling-viz，均 MIT，只借做法。）

- **一镜一个新概念。** 每一镜开工前写一句「观众该看的那一个东西是什么」，它最亮最大；上下文压暗到 0.3 到 0.4，网格、坐标压到 0.15。
- **同一个对象全片同一位置、同一画法。**
- **先出画面，再念到它。** 画面比旁白早 0.2 到 0.5 秒出现。
- **一张数据图只讲一个结论。** 标题直接写结论；能用一个大数字说清的不画图；小方块矩阵看不清时换成大数字、点图或单条折线。
- **顺序用动画，部位用静图。** 「先 X，再 Y」用动画一步步做；「看这几处」放一张静图依次高亮。
- **留白至少 15%**，节奏有快有慢，核心结论停够时间。
- **不用闪烁表示状态**，闪烁看着像故障。「空着、待补」用静止的虚线框。
- **不做骗眼睛的动画。** 不先画成全绿再变红，第一次出现就是真实状态。柱子增长时不显示中间数值，长到头才出现最终数字。
- **不画原文没给的数。** 原文只有结论没有数据时，只放标签，不编示意柱子。
- 纵轴不从 0 开始时每个点旁标数值。
- 会随内容增长的区域，框跟着内容长，不先画一个大空框等着填满。
- 不留空屏：结论句不要把上一镜清空、只剩两个小标签。结论落在上一镜的图上（圈出、标注、变色），或者换一张填满主体的新图。
- 别人的结构图只借结构和通用术语，说明文字用自己的话，用代码重画。旁白不说「这张图」「图上写着」，图里的内容直接当知识讲。

## 真实素材

- **资讯、博客、榜单、论文**：放官网或主流媒体页面的真实截图，带浏览器外框和真实网址，讲到哪句就高亮哪句。用 `scripts/capture.py`：在 `JOBS` 里写网址和要高亮的原文片段，它滚到关键句附近截图，并把每个片段的位置存进 `meta.json` 供画面画高亮框。
- **模型和产品**：放真实 logo，优先用 simple-icons 这类开源图标。
- 不用 AI 生成这类素材。
- 截图只在能证明正在讲的那句话时才放，要截到能证明画面标签的原文（表格没有表头时连上方说明句一起截）。营销首页看不出和那句话的关系，用 logo 卡片代替。
- 每份资料只留一张截图、停 2 到 3 秒证明出处。截图里的结论改用原文的真实数据画成图，不要让截图占掉可视化的时间。
- 单独一张截图的镜头，截图放大到接近全宽（约 1700 像素），底边不压字幕。
- 截不到的页面（人机验证等）把网址发给用户，请他截图。
- 自己编的示例，面板标题写「举例」。

## 画面上不放的东西

- 来源角标、红色「示意」标签都不要。出处统一放片尾资料卡（无旁白，约 5 秒）。
- 片尾资料卡只放数据和代码的出处，不放写作参考。代码和面板标题只写文件名，不写目录路径。

## 镜头五条

（借鉴 video-talkcraft 的做法；它只允许非商业使用，代码自己写。）

1. 截图像手持镜头一样慢慢滚动，到关键句减速停住，再高亮。
2. 每一节一个极缓推近（1.00 → 1.035），截图和其他元素用同一台机位。
3. 不硬切：旧画面继续推近淡出，新画面从略远处推入。同一张图的两个版本不交叉淡化，先淡出一版再淡入另一版，否则有残影。
4. 开场留空不超过 1.5 秒（配音从 1.2 秒开始，画面 0.3 秒出现）。开场标题先退场，再放内容，一屏只放当前在讲的东西。
5. 用逐词时间戳对齐：字幕切换和动作挂在具体某个词出现的时刻（`window.WORDS`，在场景里用 `wt(id, 词)` 取时间），不按字数估。

## 排版自查

- 文字不压框线：标签、标题放在框外上方，留 10 像素以上的间距。
- 动画的终态和中间态都不能重叠。一组卡片飞到新位置时，每行间距大于卡片高度，最后一张也要查。
- 逐条出现的列表、打勾、计数，最后一项要在这一镜结束前完整显示。截帧时专门看每组的最后一项。
- 同一横向位置先后出现的两段文字，要么错开，要么前一段先退场。
- 内容区不低于 y≈880，字幕在 y≈939。字幕渲染前跑 `scripts/check_subs.py` 量宽度，超出屏幕的拆开。
- 图标、锁这类小元素放在标题行的空位上，不压在文字上。
- 交给用户前跑 `--stills` 看每个新镜头：文字有没有被半透明卡片透出来，标签和截图里的表对不对得上，数据是否真的画出来了。

## 动画锚点

- `wt(id, 词)` 找不到词时会退回句首，画面提前出现，而且不报错。改了旁白后，用脚本读 `lines.json` 的 `say`，逐个检查 `s*.js` 里 `wt` 的词是否还在，写在数组或变量里的锚点也要扫。词里带空格、引号的，字幕去空格后会找不到。
- 停顿或语速改过之后，所有动画时间都变了，渲染前重新出拼图检查。

## 自查命令（不算渲染，随时可跑）

```
python <engine>/render.py . --sheet 16
python <engine>/render.py . --stills 33 121 200
python <engine>/render.py . --motion 120 124
```

## 渲染（闸门 2 之后才能跑）

`scripts/render_all.sh`：`render.py . --jobs 6` 出 `renders/raw.mp4`，再合上配音：

```
ffmpeg -y -i renders/raw.mp4 -i voice.wav -map 0:v -map 1:a -c:v copy -c:a aac -b:a 192k -t "$DUR" -movflags +faststart out.mp4
```

`DUR` 取 `timings.js` 里的 `END`。成片覆盖前把旧版另存一份，文件名里写明时长。参考耗时：7 分半的片子 6 路并行约 20 到 30 分钟。

## 小改动只渲片段

- 只改一两句配音或几处画面时，不重渲全片。配音按 voice_rules「只改一句时」贴回原起点，`timings.js` 不动，后面的时间轴就不会挪。
- 画面用 `--clip a b 名字` 只渲改动所在的那几秒（起止对齐整帧），再和旧成片其余部分 concat 拼接。concat 列表写绝对路径，拼接加 `-fflags +genpts`，否则拼接点之后的画面解不出来。拼完用 ffmpeg 解几帧验证。
- 只改配音、画面没变时，用 `-c:v copy` 把旧画面和新音轨重新封装，几秒钟完成。
- 新配音比原句长、贴不回原位置时，先告诉用户只能整片重渲，以及大概要多久。

## 插入新段落时只渲片段

- 新段落用新的节号，节内旧句子一个字不动，旧句子的配音不重合成。
- 用 HOLD 把每段插入的时长补成 1/30 秒的整数倍，插入点后面的旧画面才能按帧号原样复用。
- 前一节的退场时间改成新节开始，`film.js` 的节顺序按播放顺序排。
- 背景里按绝对时间动的东西（地面网格）改成按上一版的时间走，插入段里停住，拼接处不跳。
- 只渲新段落前后各多 1 秒；用 ffmpeg trim（按帧号）把旧成片切开，和新片段 concat，整片重新编码一次，合上新的 `voice.wav`。

## 踩过的坑

- ffmpeg 不要把 `apad` 和 `-shortest` 一起用，进程会停不下来。用 `-t` 截断。
- macOS 没有 `timeout` 命令，后台脚本用了它会直接退出、退出码却是 0。跑完检查产物是否真的生成。退出码 143 是进程被手动结束。
- 渲染偶尔有一段因浏览器启动超时失败，每段要带重试，只补失败的那几段。
- 内容要改时先停掉正在跑的旧渲染（连同重试循环），避免旧版覆盖成品。`renders/raw.mp4` 在新渲染完成前是旧版，别拿来交付。
- 用户问进度时，看分段文件 `renders/_partNN.mp4` 的大小估算完成比例，如实报时间。
- 没有 ffprobe 时用 `ffmpeg -i` 看时长和音轨。
