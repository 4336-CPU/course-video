# 配音细则

模型听不到声音，所以每条都配了能用数据检查的办法。

## 两套配音

- **草稿**：Edge TTS（免费），`zh-CN-YunxiNeural` 男声，`rate=-15%`，同时取逐词时间戳。内容全部定稿前一律用它。Edge 念英文词前常有停顿，没法指定多音字读音，能换词就换词（「一行提示」→「一句提示」）。
- **正式**：MiniMax 官方 TTS（`speech-2.8-hd`），用现成音色，不复刻任何人的声音。用户同意付费后才用。计费字数约是汉字数的两倍，2,200 字的稿子配一遍一两元。
- 估时长：MiniMax 比 Edge 快，同一份稿 Edge 7 分 43 秒，MiniMax 6 分 10 秒。按 MiniMax 每秒约 4.9 字估。

## 读法：先理解意思，再写给 TTS 的文字

- 字幕（`sub`）和读法（`say`）分开写。读法按人会怎么念来写。
- 文件名里的点、下划线、斜杠不念：`train.log` → `train log`，`read_file` → `read file`，`output/` → `output`。写成 `train.log` 会念成 dot，写成「train点log」会把「点」念出来。
- 英文技术词按程序员口头读法：JSON 写成 Jason；缩写先查惯用读法（ICLR → eye clear，NVIDIA → 英伟达）。
- 数字转汉字，读数末尾的 0 不念（0.9240 → 零点九二四）；年份逐位念（2026年 → 二零二六年）。
- 中英文、中文和数字之间不留空格，TTS 会在空格处停顿。
- 两个引号挨着时中间补顿号，免得两段英文连读。
- `../` 这类符号不念，读法里改成说意思。
- 相邻两个字会连成别的词时调整语序（「写好看目录」会被听成「好看」）。
- 「X的是」会把「的」念成 dì，换个写法。
- 多音字放进 `pronunciation.json`，整表传给 MiniMax 的 `pronunciation_dict`。常见的：行（háng：一行一行、十来行）、得（děi：就得）、转（zhuàn：转很多轮）、重（chóng：重复）、处（chǔ：处理）、挑中（tiāo zhòng）、校准（jiào zhǔn）。每版都逐字查一遍。
- 有歧义的断句先试合成看时间戳。试过仍然断错才改读法，改字幕前先问用户。

## 语气和语速

- **全稿统一 `emotion: calm`。** 不指定情绪时 MiniMax 每句自己猜语气：同一句两次合成能差 1 秒，词中间会断开，带英文工具名的句子语调突然抬高。只给个别句子加 calm 会让前后语气不一致。
- calm 下 speed 1.1 约每秒 4.9 字。speed 1.0 会被嫌「太慢」。
- **语速要一致。** `voice.py minimax` 合成完自动算每句的字/秒（汉字算 1、英文单词算 2，不到 12 字的短句不算），偏离中位数超过 10% 的按 `speed × 中位数 / 实际字速` 改 speed 重合成一次。
- **查词中间的断开。** 用逐字时间戳算每个字占的时长。句首和逗号后的第一个字天然偏长，不算；词中间的字超过全句中位数 2.3 倍，多半是被拉长或断开了，重抽几次，挑最连贯的一版。

## 停顿

- 句间停顿统一：`GAP 0.35 + HOLD_DEFAULT 0.45`，约 0.8 秒。时长忽长忽短会被听出来。
- 只有这几处加长：问完问题等答案出来（1.0）、留给观众想的问题（3.0）、全片最后一句（1.5）。节与节之间另加 `SEC_GAP 1.1`。
- 不为了等动画加停顿。动画跟不上就改动画的时间点。
- 停顿改过之后，所有动画时间都会变，渲染前重看拼图。

## 只改一句时

1. 改读法，重新生成 `lines.json`。
2. 备份 `voice.wav`、`timings.js` 和 `voice_minimax/`。
3. 用 `voice.py minimax 编号=语速` 只重合成这一句，用原来的语速。挑时长最接近原句的一版，新音频不能长过下一句的起点。
4. 按原起点贴回 `voice.wav`，`timings.js` 不动。
5. 用 ffmpeg 把旧成片的画面和新音轨重新封装（`-c:v copy`），不用重渲画面。

只加几句新句子时：`voice.py minimax 新编号=1.1 ...` 只合成新句子，再 `voice.py minimax none=1` 只重排时间轴，不会顺带重合成旧句子。

## 接口细节（MiniMax）

- `POST https://api.minimaxi.com/v1/t2a_v2`，Bearer Key 从环境变量 `MINIMAX_API_KEY` 读，不写进脚本和文档。
- `subtitle_enable: true` 加 `subtitle_type: "word"` 才返回逐字时间戳（毫秒，`timestamped_words`），存成 `<id>.words.json`，和 Edge 一样驱动 `wt()`。
- 并发 2 路仍会偶尔撞每分钟请求数限流（错误码 1002），脚本自动等 8 秒重试。
- 缓存按「音色、情绪、读法」校验，读法改了才重合成。语速由校准那一遍决定，记在 `<id>.speed`。
- Edge 偶尔卡在网络请求上：每句限时 60 秒，失败重试 5 次。缓存要核对句子原文（`<id>.txt`），只认编号会把旧稿的录音接到新句子上。

## 逐字时间戳的坑

- 读音表里的词，MiniMax 返回的 `timestamped_words` 里会混进注音条目（如 `(hang2)`），要跳过。每个词只在当前位置附近找，找不到就留在原位，不往后推；往后推会让整句后面的时间全部错位，字幕和动作整体提前。
- 检查办法：每句的位置严格递增、不落在标点上、不超过读法长度。不满足的句子，用同样参数再合成一次参考音频拿时间戳，按时长比例映射到现有录音上。
- 交付前模拟一遍字幕切段，查出时长不到 0.8 秒、或每秒超过 9 个汉字的段。字幕下一段开头带引号时容易在读法里找不到，退回句首。
